# Specialist design workflow

Apply this to substantial visual work. This is a native Codex adaptation of the coordination and shared-context idea described in the [supplied reel](https://www.instagram.com/reel/Da5be6dJ6Fi/). Its caption promotes [Ruflo](https://github.com/ruvnet/ruflo). The video and its performance claims were not verified. This workflow does not install Ruflo, provide automatic model routing, or claim token savings.

## One shared brief

Reuse the project's existing design brief or decision record. If none exists, keep a compact `design-brief.md` with the task artefacts, outside application source. Record the four inputs, source links, explicit constraints, approved direction, chosen body variant, relevant type/colour/spacing decisions, preview location and outstanding issues. Label assumptions and proposals separately from Oliver's choices. Use synthetic content when real data is unnecessary.

Update the record after a decision or verified result, not after every tool call. Future tasks should read the relevant record before inventing a new direction. Do not overwrite global memories, turn one project's taste into a universal rule, or share private context with external services.

## Scoped specialists

When native delegation is available and authorised, delegate reference/code exploration and use a separate reviewer for substantial work. Keep a maximum of three child agents, within the environment's actual limit. Only run independent work concurrently.

- **Researcher, read-only:** identify the existing visual system and component patterns; analyse supplied references for transferable qualities; return a short evidence-backed set of constraints and opportunities. Read only relevant files.
- **Builder:** implement the selected direction and variant in the existing stack. If delegated, assign exact file ownership, tell the worker others are in the codebase, and prohibit reverting their work.
- **Reviewer, read-only:** inspect the rendered result against the brief, including desktop/mobile and relevant interaction states. Receive the brief and actual artefacts, not the builder's desired verdict. Return concrete findings with view, evidence and the smallest useful correction.

The lead coordinates choices and owns the shared record. Skip roles with no useful task. If delegation is unavailable, perform the roles sequentially and disclose that the review was a self-review. Do not invent agents, consensus, shared memory, automatic learning or visual evidence.

## Selection and implementation

Present five distinct directions, then honour Oliver's choice or an already-clear choice. Do not let agent consensus substitute for it. Present three body variants inside that direction. Use flat CSS imagery until selection; create the original hero asset afterwards with the available image/design tools. Keep reference work about feel and technique, not copying.

Use existing components, assets, fonts and tokens first. Use `design-resource-library` only when a real resource is missing and that skill is available. Its local catalogue is optional: in cloud environments without it, use current official resource sites and verify licences. Do not add a package, provider, paid service or background daemon just to run this workflow.

## Evidence and correction

Use the running preview and its live tweaks panel. Record the actual inspected viewport sizes and screenshots or view references. For an interface, inspect keyboard focus, readable contrast, primary interaction, overflow and relevant empty/error/loading states. For a static creative asset, inspect it at its intended display or print size. Make no claim about a view or interaction that was not inspected.

Have the reviewer prioritise hierarchy, typography, composition, distinctive character, content accuracy, accessibility and responsive behaviour. Correct the largest evidenced problems first, using small changes and at most two correction passes. If preview access is blocked, continue independent reversible preparation and report the blocker before claiming visual completion.

Keep design selection, local checks, visual review, regulated approval and publication as separate statuses. Preserve all project safeguards, including financial-promotion approval, child-data safeguards and the no-commit/no-push rule. At handoff, state the chosen direction, what was inspected, remaining issues and any required approval.
